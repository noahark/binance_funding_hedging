## Goal

### 已核实的事实（不要重新调查）

`_avg_price_decimal`（`live_hedge_executor.py:93-97`）判零条件为
`raw in (None, "", "0", 0)`，**只认字面 `"0"`**。Bookkeeper 在固定提交上实测：

```
'0'        -> None       ✓
'0.00000'  -> '0.00000'  ✗   ← 币安 USDⓈ-M 查询订单的实际返回格式
'0.0'      -> '0.0'      ✗
0          -> None       ✓
'50000.12' -> '50000.12' ✓
```

币安 USDⓈ-M「查询订单」官方示例为 `status=NEW`、`executedQty=0`、`cumQuote=0`、
**`avgPrice="0.00000"`**。该值会被落库并在日志表显示为均价 `0.00000`——用户会读成
「成交价是零」，而事实是「还没成交」。这违反本 stage 的钱的展示硬约束。

### 钉死的修法（两层）

**第一层（主修复，解析层）**：`_avg_price_decimal` 的判零改为**数值判零**——任何可解析
为数值零的输入（`"0"`、`"0.00000"`、`"0.0"`、`0`、`"0E-8"` 等）一律返回 `None`；
非零值原样保留、不做格式化改动。无法解析的输入仍返回 `None`。

**第二层（纵深防御，展示层）**：`_resolve_avg_price`（`service.py:205`）在取用库存值
之前也做同样的数值判零——库存值为数值零时**视为未知**，退回本地计算（②），而不是把
`0` 展示出去。

理由：① 已落库的脏数据（若有）不会因为解析层修好就自动消失；② 未来若出现别的写入
路径，展示层是最后一道关；③ 均价为零在业务上不可能是真实成交价。

### 硬约束

1. **不得动 `_quote_decimal`。** 成交额的 `"0"` 是**真实的零成交**（合法值），与均价的
   零含义完全不同——`cumulative_quote_amt` 的 T1 NULL 契约（NULL=未知、"0"=真实零）
   必须原样保留。**这是本轮最容易改错的地方。**
2. **不得改变非零值的表示**：`"50000.12"` 进、`"50000.12"` 出，不做补零、不做截断、
   不做科学计数法转换。
3. 不碰状态机、调度、结算判定、计数器、暂停/删除、worker、`aggregate_positions`、
   下单行为。

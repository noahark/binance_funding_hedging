# 04 前端 fake 样式任务规格（Planner 交付，供 Bookkeeper 组装 dispatch）

本文件是任务内容规格，不是 dispatch packet。Bookkeeper 据此生成 `04-fake-frontend.dispatch.md`。

- 目标模型：**Grok 4.6**（provider `xai`，Herdr 窗口标签 `grok`，非 review 窗口）
- 需求权威：`docs/planning/smooth-close-orders-v1.md`（r3，已通过第三次跨 provider 计划评审 ACCEPT）
- 前置状态：后端**尚未实现**。本任务只做静态样式预览，Human 页面验收通过后才会启动后端 P1。

## 1. 目标与性质

让 Human 在真实页面上先看清平滑平仓的**布局、文案和信息密度**，在写后端之前就把展示层的取舍定下来。

**这是 fake 样式预览，不是可执行功能。** 所有新加的控件与卡片必须明确标注"样式预览、不执行"，且不得发出任何真实请求。此做法沿用平滑开单 V1 的同类前置任务（见 `docs/planning/smooth-open-orders-v1.md` §12）。

## 2. 允许修改的文件

- `frontend/index.html`（唯一）

不得修改后端任何文件、不得新增文件、不得改动 `frontend/self-check.js` 的既有断言。

## 3. 要做的四块

### 3.1 私有持仓面板的平仓操作列

在现有"立即平仓"列的基础上，镜像市场表开单列的布局，加入平滑平仓入口：

```text
[平滑平仓] [ 0.05 ] %    [立即平仓]
```

- 阈值输入框默认 `0.05`，允许负号与最多两位小数（前端仅做输入形态展示，不做提交）；
- 与现有"单次平仓币量 / 计划尝试次数"两个输入并存，不破坏现有布局；
- 现有"立即平仓"按钮的行为与外观**零改动**。

### 3.2 确认弹框

点击「平滑平仓」弹出确认框（仅展示，确认后不发请求，提示"样式预览、不执行"）：

- 回显币种、方向、单次平仓币量、计划尝试次数；
- 回显**滑点阈值 `x.xx%`**，并说明比较的是**当前方向平仓率**（不是开单率）。

### 3.3 fake 平仓任务卡（在任务页"执行中"区域插入，明确标注不可执行）

需要覆盖以下**五种形态**，让 Human 一次看全：

1. **未备料 / 已暂停**：显示备料状态"未备料"，启动按钮可点；
2. **备料中**：启动按钮显示"备料中…"，**该卡全部操作按钮（启动、暂停、删除、成交1次）一并置灰**；
3. **备料失败 / 已暂停**：显示暂停原因行，文案用后端既有三条之一，例如"平仓现货余额检查/划转失败，任务已暂停（fail-closed，未发单）"；备料状态仍为"未备料"；
4. **运行中（已备料）**：备料状态"已备料"，渲染 3.4 的动态盘口块，`成交1次` 按钮可点；
5. **立即平仓卡（对照）**：备料状态显示"每轮实时校验"，**不渲染**动态盘口块。

所有平滑卡**不得**出现"立即成交所有"按钮。

### 3.4 任务卡动态盘口块（仅运行中的平滑平仓卡渲染）

格式对齐市场页与平滑开单卡，但**语义必须是平仓**：

- 两列的标题**不得出现"开单率"字样**；
- 必须让操作员一眼看出**本任务实际参与判定的是哪一列**（正向平仓用的是"现货买一 + 合约卖一"那一组，反向平仓用的是"合约买一 + 现货卖一"那一组）；建议对当前列做视觉强调并标注方向；
- 每列展示参与计算的两腿价格与一档数量、带符号百分比（沿用现有正负颜色规则）；
- 展示两腿一档覆盖率与是否达标（80%）；
- 展示当前 gate 轮次、倒计时、等待原因；**等待原因文案不得出现"开单率"**（fake 数据里请写成平仓语义，例如"等待当前方向平仓率严格大于阈值"）；
- 展示固化的滑点阈值。

## 4. 硬禁令

- **不得发出任何真实请求**：不调用建卡、启动、暂停、删除、成交1次、闸门等任何接口；fake 控件一律阻止默认提交；
- 不得改动现有立即开单、平滑开单、立即平仓、借币、还款、划转、资产互转的任何真实行为与外观；
- 不得引入新的定时器（`setInterval`/`setTimeout` 轮询）；fake 卡是静态样式，不需要刷新；
- 不得引入任何外部依赖、CDN、字体或图片；
- 不得改后端、不得启动服务、不得创建任务、不得下单；
- 不得 `push`、`merge`、切换分支。

## 5. 验收

1. 打开页面，上述四块均可见；fake 元素带明确的"样式预览、不执行"标注；
2. 点击任何 fake 控件都不产生网络请求（浏览器 Network 面板为准）；
3. 现有页面功能与外观无回归；
4. `node frontend/self-check.js` 通过（若仓库既有跑法不同，按既有跑法）；
5. 交付为**当前 stage 分支上的一次提交**；不 push、不 merge。

## 6. 明确不做

- 不接后端、不定义或冻结 API 字段名（后端 P1 才冻结契约）；
- 不实现真实的输入校验规则（服务端才是权威）；
- 不做动画、不做响应式重构、不做主题；
- 不改任何既有中文文案，除非本规格明确要求。

## 7. 交付后

Human 页面验收。验收通过后才启动后端 P1；届时前端会按冻结的 API 契约把 fake 改成真实实现，本次的样式与文案结论直接沿用。

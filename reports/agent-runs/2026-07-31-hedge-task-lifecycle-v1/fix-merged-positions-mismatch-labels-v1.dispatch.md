1. **`no_task` 行的成本被填成 `"0"`**：`domain.py:1403-1421` `_merge_empty_bucket_row` 把 `spot_avg` / `perp_avg` / `position_qty` 等一律填 `"0"`。

### G5｜成交金额记成字面 `0` 时，均价必须按「未知」处理（真机发现，Human 指定折入）

**真机上已经出错了。** `RSRUSDT 正向` 行显示 **合约均价 `0.000623`、开单价差率 `-100.0000%`**，而真实均价约 `0.001246`、真实价差约 `+0.3%`。

数据库核对（`44-` §3）：该任务合约腿两组成交各 10000，其中一组的 `cumulative_quote_amt` 是**字面量 `"0"`**（币安 2026-07-14 移除了 UM 下单返回的成交金额字段，该腿把"未知"存成了 0）。于是 `perp_avg = (0 + 12.46) / 20000`，**恰为真实值的一半**。

**保护为什么没生效**：`aggregate_positions` 对 `NULL` 金额有 T1 §1(d) 保护（计入数量、不计入名义额、置 `perp_avg_price_incomplete`），但**字面 `0` 作为真实名义额通过**，既污染均价又不触发标记。且合并表**从不渲染** `spot_avg_price_incomplete` / `perp_avg_price_incomplete` 这两个后端已有的标记位。

**要求**：

1. 数量 > 0 而金额为零时，**与金额为 `NULL` 同等对待** —— 不计入均价的名义额，并置对应的 `*_avg_price_incomplete` 标记。
2. **把这两个标记在合并表上显示出来**（例如均价旁的提示或行标记），让用户知道"这个均价是在部分数据上算出来的"。
3. 加测试锁定：一条腿金额为字面 `"0"`、另一条正常时，均价**不被拉低**且不完整标记为真。**`RSRUSDT 正向` 的真实数据形状（10000/`"0"` + 10000/`12.46`）就是现成的测试向量。**

**范围说明**：写入端把未知存成 `"0"` 是 pre-existing（早于 `base_sha` 的实盘写路径），**不在本轮修复范围** —— 本轮只处理**读取与展示侧不得把它当真值**。若你认为写入端也必须同时改才能自洽，**停止并报告**，不要自行扩大。

### G6｜全仓借款不得在同币多行重复呈现（真机发现）

`RSRUSDT` 的两行（正向 / 反向）都显示 `全仓借款 370,036.92992257`。该数值是**按资产**的账户级借款，不是按行的持仓属性 —— 竖向加总会得出双倍负债。

## 对 v2 §11 六个问题的回答

### Q1：v2 是否仍可能压掉真实低概率高损失问题？

**我构造了六类候选反例逐一试门，全部能正确入场或被正确上交，未找到被误压的当
前可达场景：**

1. **1000x 乘数币类（推导型资金风险）**：当前前提存在（乘数映射在表、两腿共用
   `q_common`），凭据为「单位/倍率公式的直接推导与样本」→ 条件 2 准入。✓
2. **并发透支类**：两个真实入口 + 共享可变状态 + 无互斥的论证是明列凭据。✓
3. **交易所契约允许但未出现的事件（omission 类）**：「外部可发生事件 + 我方缺少
   处置分支」是明列凭据，`order_state_unknown_final` 的历史处理正属此类。✓
4. **展示误导类（我上轮 R3 的口子）**：有证据的展示谎言走条件 1「当前可达」直接
   入场（F4 当年即有实测证据）；omission 形态的展示谎言（读不到时缺少处置分支）
   走 omission 凭据入场。唯一被门挡的是「无证据猜测展示可能错」——挡它正是本方
   案的目的。R3 的实质风险已被条件 1 与 omission 凭据覆盖，不要求再改例外清单。
5. **推导型非资金缺陷（如定时任务在确定到来的外部事件上出错）**：行为现在可推
   导，凭据成立。✓
6. **无法证实也无法证伪的资金场景**：不静默丢弃、不直接 REWORK，具名上交
   Human——灰区有了出口，这是 v2 相对 v1 最重要的安全改进。✓

**(d) 残留观察（非阻塞）**：§3「一般不进入给 Human 的摘要」+§10「摘要中未通过
准入的假设场景数量为 0」测量的是报告的缺席；缺席也可能来自模型停止寻找（发现萎
缩）。这是任何此类门都固有的行为风险，合同文字无法强制「思考」。v2 的补偿是
§10 的急停条款（资金缺陷被误放行并进入合并即停止试运行），方向正确。我接受
「观察限量」的驳回理由：非资金的一次性假设本来就不值得占 Human 时间，这正是
60% 问题的根源。

### Q2：哪条准入文字仍可能被用来扩大范围或制造 REWORK？

逐条反向滥用测试后，凭据清单的每一项都要求**可核验**，伪造凭据等于伪造可执行证
据，会被 Bookkeeper 核验或复跑直接揭穿，这不是文字能再收紧的层。两个最可能被尝
试的走私通道及其现状：

- **「文件:行号」引用真实但不支撑主张**：§3 已要求凭据「支撑主张」，§9 有泛泛
  散文不合格的对应行。够了——剩下的核验成本正是 Bookkeeper 的既有职责。
- **omission 断言（「我方缺少处置分支」随口说）**：必须同时给出外部可发生事件
  的契约/文档凭据，两条都要核验。够了。

未发现仍需文字收紧的通道。

### Q3：不扩展 contested、不建排除账本、不改 reviewer skills 是否有工作流缺口？

- **contested**：REWORK 争议在现有规则下本就流向 Human（Human 边界），v2 不新
  造缺口；「不授权 Bookkeeper 覆盖 Reviewer verdict」与现有「无 ACCEPT 即非接
  受」一致，是正确的保守。
- **排除账本**：被驳回场景的去向复用 `PROJECT_STATE.md` 既有「领域事实」机制
  （bStock 条是现成先例），且进入权在 Human。不建新账本正确。
- **reviewer skills**：启动第一步必读 `AGENTS.md`，证据门写进 §1/§8 后自然生
  效；§8 留有证据触发的 Tripwire（试运行证明持续覆盖上位规则再另开任务），与全
  案哲学一致。无缺口。

### Q4：三文件范围与单一权威安排是否成立？

成立。门只长在 `AGENTS.md` §1，评审执行口径在 §8 指向它，discipline 不复述门，
skill override 指向 discipline 不复制清单——每类规则一个家，与 Harness §2 一致。
reviewer skills 与 architect/planner skills 不动的判断，我核对过各文件现有
override 指针模式，确认无遗漏职责。

### Q5：第 9 节案例能否区分「真实安全发现」和「无证据假设」？缺哪个关键案例？

14 行案例覆盖了两侧的判别要点（推导/并发/omission/契约值可入场；多重叠加/便宜
借口/散文凭据/勿议重提被挡；灰区上交）。**不缺关键案例。** 可选增一条（非必
须）：「余额/持仓读不到却显示可用（有实测或代码证据）→ 当前可达，可阻塞」，把
F4 的教训钉进表里；不入表也不影响门的判别力，因为 omission 行已覆盖机制。

### Q6：是否存在更小且同样安全、可验收的修改？

v2 已较 v1 显著瘦身（砍六字段模板、砍完整阶梯、discipline 只补三点）。再砍的唯
一候选是 discipline 三点，但「验收通过后停止扩张」正对 60% 问题里的实现侧镀金，
砍了覆盖不全。**三文件、三处写入点已是充分小。**

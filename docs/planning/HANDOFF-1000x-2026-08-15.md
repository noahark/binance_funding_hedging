## 0. 一句话

六个乘数币（`BONK / FLOKI / LUNC / PEPE / SHIB / XEC`）的合约「按箱卖」、现货「按瓶卖」，

## 1. 已定的设计口径（Human 拍板，勿再推翻）

表里存**一个倍数**，派生每条腿一对乘数：

| 腿 | `x`（价格乘数） | `y`（数量乘数） |
|---|---|---|
| 现货腿 | `1` | `1` |
| 合约腿 | `1 ÷ 倍数` | `倍数` |

```
任一腿的价格 × 该腿 x = 标准价（每个币多少 USDT）
任一腿的数量 × 该腿 y = 标准量（多少个币）
```

**在开仓、平仓、平滑、展示的每一条路径上统一施加。** 表外标的两乘数均为 1，乘完恒等——
现有全部标的行为不变，且**无需任何 `if` 判断**。

⚠️ **方向相反是最易翻车处**：一箱装一千瓶 → 箱数少、箱价高 → **数量乘、价格除**。
搞反不报错，只会算出一个看似正常、实际错一百万倍的结果。

⚠️ `x` 与 `y` **必须由同一个倍数派生**，不得各存一列（两列可互相矛盾且系统无法自检）。

## 4. 三条反复踩到的教训（接手必读）

### 4.1 按语义横扫，不要按文件打补丁

「两腿价差」这个概念在系统里有**三份彼此独立的实现**，数据源各不相同：

```
市场表开单率      snapshot.py:698        ← 盘口报价
历史页滑点        store.py:2563          ← 后端成交记录
持仓表开单价差率  frontend/index.html:5249 ← 前端成交记录（JS 重写）
```

**r1 漏了全部三处，r2 补了两处仍漏第三处。** 根因是按文件逐个改。
同样的形状出现在发单数量（三处装配点，r1 只找到 1/3）。

⚠️ **改动一落地后计数不会减少。** 前置轮方案曾称「§3.5 从三处降为两处」——**该说法错误**
（grok F3）。即使做了改动二，也只是 JS 那行换成 `aggregate_positions` 就地公式，仍是三处。
**按「两处」规划会再次漏掉持仓表。**

### 4.2 单元测试在量纲错误上会假绿

`PROJECT_STATE` 反复警告的形状，本轮找到了两个具体机制：

- 真执行器与假执行器各持一份换算 → **已由改动一消除**
- `fakes.py:207-214` 模拟成交给两腿喂**同一个数量、同一个价** → **未消除**，
  r3 §8.2 约束 C 已写明必须拆开

r3 §8.2 有四条反自证约束（A/B/C/D），实现时逐条执行，不要跳过。

### 4.3 行号会漂，动手前必跑校验

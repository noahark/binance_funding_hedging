## 0. 为什么散文规则不够

r4 §2.6 写的是一条散文规则：「对账数字保持原样，比较数字才换算」。
三方评审对它给出了三种读法：

| 评审 | 对 §2.6 的判定 |
|---|---|
| `agy` (gemini-3.7-flash) | 「自洽，无误导性」——**错**，持仓表实际有冲突 |
| `claude-glm` | 「规则自洽，但行内有两个误导路径」——发现了持仓表，**漏了历史页** |
| `grok` | 「**自相矛盾**」——发现了历史页，判 REWORK |

三家都没数全，且**历史页整张表在 r1–r4 四轮里从未被任何人提及**。
根因：前四轮都按「两腿价差」这个语义横扫，而历史页**不算价差**，它显示的是
逐腿的数量、价格与成交额，搜 `spread` / `basis` / `slippage` 一个都搜不到它。

**结论：这类路径必须按「界面上出现的每一格」枚举，不能按语义搜。**

## 1. 判定原则（取代 r4 §2.6 的散文规则）

每一格三选一：

| 标记 | 含义 | 判据 |
|---|---|---|
| **原样** | 保持交易所/账户原单位，只在表头或文案加单位标注 | 该格会被拿去与币安页面或账户对账 |
| **换算** | 乘上该腿乘数后再输出 | 该格只用于两腿互相比较，不对账 |
| **原样 + 比较副本** | 展示原值，另算一份换算值**仅供公式内部使用**，不出现在界面上 | 两者都要 |

⚠️ **默认是「原样」，不是「换算」。** 这与 r4 §2.3「全路径统一施加」的默认相反——
见 §7 的设计更正。


## 7. 设计更正：「全路径统一施加」只对计算成立，对展示不成立

r4 §2.3 主张「换算必须在每个边界发生」，并把展示与计算一并归入。
**按本清单逐格数完，该主张对展示层不成立：**

```
计算路径（比较、判定、下单）   →  必须换算       ← §2.3 成立
展示路径（界面上的每一格）     →  默认原样 + 标注  ← §2.3 不成立
```

**25 格中，处置为「换算」的只有 3 类**：开单价差率（比较副本）、
历史页滑点、市场表开单率。**其余 22 格全部是「原样 + 单位标注」或「无量纲问题」。**

这个比例本身就是证据：r4 把「统一施加」当成展示层的默认，方向反了。
默认取错会让实现者倾向于多改，而**多改的方向正是第 11、15、24 格「改了就错」的方向**。

### 对工作量估算的影响

r4 §0.5 给的「约 15 个改动点、400–600 行」**基于 r4 §3.5 的「展示 3 处」，已不作数**。
按本清单，展示层实际是 25 格；但因绝大多数处置是「加单位标注」而非「改公式」，
**增量主要落在 UI 文案而非逻辑**。r5 须重新给出估算，不得沿用旧数。
